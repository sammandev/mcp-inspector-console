# Task 5 Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render a static, responsive Phase 0 combined inspector shell using mcp-use's published theme and export registry.

**Architecture:** A local `AppShell` owns navigation and theme state while `FeaturePlaceholder` renders capability-aware route placeholders. `App` supplies the published `ThemeProvider`, one connection selector, and offline scaffold notice without mounting any live MCP provider.

**Tech Stack:** React 19, TypeScript, Vite, Vitest, Playwright, Tailwind CSS 4, mcp-use inspector public exports.

**Spec:** `.superpowers/sdd/2026-11-24-phase-0/task-5-brief.md` and `combined-mcp-inspector-design.md`

## Global Constraints

- No `McpClientProvider`, connection, or live session in Phase 0.
- Use published mcp-use exports/CSS only; no deep imports or copied upstream shell.
- Preserve Task 4 Tailwind source sentinel coverage.
- One connection selector, capability destinations, desktop/mobile navigation, accessible controls, stable Playwright selectors.
- Windows-safe commands; Node >=22.23.4; no upstream modifications.

## Review Focus

- Multiple visible navigation landmarks on responsive breakpoints: unit and browser assertions pin the intended single desktop/mobile control.
- Theme provider API or token mismatch: browser test verifies toggling changes the document theme and preserves primary visual tokens.
- Accidental live provider usage: source-level regression test rejects `McpClientProvider` and deep imports.
- Capability labels drifting from the contract: registry-driven tests assert all fourteen destinations.
- Tailwind source proof removal: existing Task 4 test remains intact and is rerun.
